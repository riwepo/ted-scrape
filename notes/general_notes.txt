-- Intro --
This project calls a webs service (srape-api) to return the HTML of a TED Talk Transcript web page

The urls of these web pages are all the same except for the slug.

here is a url I used to test stuff

https://www.ted.com/talks/eric_schmidt_the_ai_revolution_is_underhyped/transcript

-- Getting page HTML --
In order to scrape the html, you need a headless browser
I have used puppeteer.js
After trying several different ways to run this,
I have decided the best way is as a web service in a docker container
on the local machine it is running on port 3001
here is a sample curl command
curl -X POST http://localhost:3001/scrape -H "Content-Type: application/json" -d '{"url": "https://www.ted.com/talks/eric_schmidt_the_ai_revolution_is_underhyped/transcript", "selector": "button > div > i:first-of-type" }'
the parameters are 'url' and 'selector'
selector string is used in a waitForSelector function in puppeteer
the one I have chosen targets a button
once this appears, the page is ready to be scraped
the web service returns the entire html of the page
scraping the webpage takes a few seconds, so in dev mode it is handy to save it as a file
and use that file as input to parse.clj
this is all handled in extract.clj

-- Getting transcript HTML --
Once we have the HTML, we have to process it to get the transcript out.

I was able to find the whole transcript in a script in the head of the document.
However it contains no paragraph splits.

Better strategy.
Each paragraph contains a recognizable button, with 2 icons and a time on the label.
I find the button nodes, then collect everything in the grandparents of those nodes.
This gives me a collection of nodes.
Each node contains a paragraph of transcript.

I process each paragraph to pull out the transcript paragraph.
This is all handled in parse.clj

-- Writing text document --
I save the transcript in an open office odt file.
The name of the file is the same as the title of the talk.
The file is saved to a directory passed on the command line.
If no arg is passed, it defaults to the current directory.
This is all handled by odt_writer.clj.

-- Using the app --
The app is packaged in a docker file.
In this version, the task is kicked off from the command line WITHIN the docker container.
Two command line arguments are url of the ted talk, and directory to store the file.
